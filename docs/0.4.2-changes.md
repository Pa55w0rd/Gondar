# 0.4.2 更新说明

本轮改动解决持续运行中的成果交付和误中断，保留已有事实、发现、报告、附件、工具配置、原授权范围及人工控制。

## 执行与保存

- 保存间隔改为软提醒，不因十五分钟未登记成果终止有效工作。提醒可关闭，真实防空转继续检查无进展次数和持续时间。
- 同一模型回合中的并发调用不会从首次提醒直接跳到终止；时钟变化、等待回显、无新增的重复保存不能制造探索进展。
- 已有材料在检查点阶段仍可读取并登记；不会为整理文件而无条件放行任意命令。
- 验证保存按配置的收尾预算增量修正，保留已成功部分。相同错误没有变化时止损，未决明细持久化交接。
- 保存确认丢失时匹配完整记录及证据引用，不用业务摘要替代保存确认；已执行的目标操作不因记账失败而重放。
- 格式错误的目标可通过明确修正关联核销，仍核对原有目标字段；无关成功不能清除旧失败。
- 续跑直接获取宿主交接材料，不要求Worker调用不可用的工具。正常结束、预算、模型故障及保存缺口分别呈现。

## 工具与模型兼容

- 旧库和运行装配均核对内置工具结构，补齐新的证据参数，保留启停、角色绑定、延迟设置、用户文案和兼容默认值。
- Worker包装层透传实际可用的证据预览能力，保留任务归属和文件边界。
- 摘要请求继承模型推理配置，移除强制禁用推理的覆盖。
- 延迟工具按实际内层工具治理，外层可信调用身份和结果配对保留；畸形、禁用、未解锁的调用在执行前拒绝。

## 配置与范围

- Agent配置页分别展示主探索预算、单次模型调用保护及收尾轮数，说明任务总时限与工具调用时限的区别。
- 主探索不限时仍使用提供商的单次调用保护；派生任务剩余时间不能把该保护延长，也不能覆盖自定义更短的调用保护。
- 持续模式明确空意图队列、零未完成目标与覆盖完成的区别，要求检查未验证条件和可执行方向。
- 规则兼容原始JSON匹配，并检查解码后的独立字符串值；代理失败路径避免关闭空连接。
- 资产查询构造层统一分组；既有调用方范围过滤保留。

验证包括独立PostgreSQL上的主模块2200项通过、20项跳过，Linux SDK含子用例365项通过，以及前端类型检查和35页静态导出。Linux SDK验证为功能回归，不是race验证；没有真实目标或业务漏洞增量验证，不承诺漏洞数量增加。
