# Web验证卡

依据当前入口、角色与已见流量选择单一假设，先建立正常/异常对照。只测已授权主机与操作，不自动扩大到同根域名、共享IP或第三方服务；重定向与新增接口先核边界。

检查输入是否经过实际解析、校验与危险操作。返回200、页面差异、弹窗或静态HTML可嵌入都不能独立证明业务影响。浏览器交互类问题需要实际受保护操作和可观察的状态变化。

自动化坐标、焦点、窗口弹出或真实用户手势受限时保留待跟进，不能因此宣称已排除风险。使用受控账号与目标操作，不执行真实支付或不可逆业务动作。

邮箱/IDNA等主体混淆沿api-security-testing核验卡检查完整接收与兑换链；其他证据规则参照pentest-verification。缺工具时记录差距，不虚构扫描或排除结果。

每个有信息增益的假设按具体端点、输入、身份/对象和变体记入 `record_verification`，用 `list_verifications` 续接已有证据。把未测、缺前提、被防护阻断、证据不足、有效阴性和影响已证实分开；一次阴性只排除实际执行的那一格，不替代其他入口和表示法的核验。

URL、回调或重定向的解析差异，沿“请求字节→应用接收值→校验解释→输出地址→实际消费者解释”保留对照。先核正常允许值与拒绝对照，再选择与已见解析链有关的有界变体，确认客户端没有额外编码。仅存在解码差异不构成漏洞；真实浏览器、取址器或兑换链不可用时保留证据缺口，不宣称排除风险，也不自动扩大接收域名范围。
